![image.png](image2.png)

#### GitHub Pages

- GitHub 저장소에 있는 정적 파일(HTML/CSS/JS)을 무료로 웹에 호스팅해주는 GitHub의 기능
- 서버·데이터베이스 없이, 저장소 안 파일을 그대로 또는 빌드 결과물을 HTTP로 서빙만 함
- `Settings → Pages`: Pages를 활성화했는지 여부가 이 설정이 나타나는 조건
- `계정명.github.io`: GitHub Pages의 사용자/조직 사이트(계정당 하나)

#### Source 모드

1. **Deploy from a branch(기본값)**: 
    - GitHub Pages 서비스 자체가 빌드를 대신 수행
    - 지정한 브랜치에 마크다운/설정 파일을 push하면, GitHub 인프라가 자체 Jekyll 환경으로 빌드를 실행
    - GitHub이 임의의 사용자 코드를 자사 인프라에서 실행시키는 것이라 보안상 제약된 환경(safe mode)으로 동작
    - `github-pages` gem이라는 고정된 gem 번들에 포함된 플러그인/테마만 허용되는 화이트리스트 방식
        - Jekyll 버전, 플러그인 버전 모두 이 번들이 지원하는 것으로 고정됨
        - 사용자가 임의의 gem이나 커스텀 Ruby 코드를 추가할 수 없음
2. **GitHub Actions:**
    - GitHub Pages가 빌드를 하지 않음
    - 사용자가 작성한 워크플로 파일(`.github/workflows/`)이 GitHub Actions 러너 위에서 `bundle exec jekyll build`를 실행함
    - 격리된 일반 CI 환경
        - `Gemfile`에 적은 **임의의 gem·버전·플러그인을 제약 없이** 쓸 수 있음
        - 빌드가 끝나면 결과물(`_site`)만 아티팩트로 올리고, GitHub Pages는 그걸 그대로 서빙만 함

### 4. 설정 파일 작성

- 위치: 저장소 루트

```
Gemfile              ← 직접 작성 (테마를 gem으로 지정)
_config.yml          ← 직접 작성 (사이트 설정)
index.html           ← 직접 작성
_tabs/about.md 등    ← 직접 작성 (메뉴 페이지)
.github/workflows/   ← 직접 작성 (배포 워크플로)
_posts/              ← 내 글
```

#### 각 파일의 역할

**필수**

| 파일 | 역할 |
| --- | --- |
| `Gemfile` | 쓸 gem 선언<br>`bundle install`의 입력 |
| `_config.yml` | 사이트 설정<br>테마 gem은 설정을 제공하지 못하므로 반드시 로컬에 있어야 함 |
| `index.html` | 홈페이지<br>`layout: home`을 지정<br>글 목록이 여기 표시됨 |
| `.github/workflows/pages-deploy.yml` | GitHub Actions 배포 워크플로<br>Pages source를 Actions로 쓰면 이게 빌드·배포를 수행 |
| `_data/contact.yml` | 사이드바 하단 아이콘 목록을 정의 |

**선택**

| 파일 | 역할 |
| --- | --- |
| `_tabs/*.md` | 사이드바 메뉴 항목<br>파일 하나가 메뉴 하나<br>gem에 포함되지 않아 로컬에 있어야 하고, 없으면 그 메뉴가 아예 안 생김 |
| `_plugins/posts-lastmod-hook.rb` | git 커밋 이력을 읽어 글에 "최종 수정일"을 자동 표시<br>빌드 시 실행되는 로컬 플러그인 |
| `.gitignore` | git 추적 제외 목록(`_site`, `.bundle` 등 빌드 산출물) |
| `_posts/*.md` | 사용자가 쓴 글 |

#### 4-1. Gemfile

- 프로젝트가 어떤 gem을 어떤 버전으로 쓸지 선언하는 파일
- Bundler에게 무엇을 설치·로드할지 알려주는 선언
- 파일명이 문자 그대로 `Gemfile` (확장자 없음)
- Ruby 문법으로 작성 됨
- `jekyll-theme-chirpy` vs `chirpy-starter`
    - `jekyll-theme-chirpy`
        - `gemspec`: "이 폴더에 있는 테마 소스를 직접 쓴다"는 뜻. 테마 소스가 같이 있어야만 동작.
        - 테마 본체 저장소의 파일을 그대로 가져오면 gem 방식이 아니라 풀소스 방식이 됨
        
        ```bash
        source "https://rubygems.org"
        gemspec                          # ← 같은 폴더의 .gemspec을 읽어 로컬 소스로 빌드
        gem "html-proofer", "~> 5.0", group: :test
        ```
        
    - `chirpy-starter`
        - `jekyll-theme-chirpy`을 받아서 사용
        - https://github.com/cotes2020/jekyll-theme-chirpy 리드미에서 gem 버전 확인 가능
        
        ```bash
        gem "jekyll-theme-chirpy", "~> 7.6"   # ← RubyGems에서 받아 사용
        ```
        
- 버전 표기법
    - `~>`:
        - 비관적 버전 제약
        - Ruby 특유의 표기
        - 마지막 자리만 올라가는 것을 허용
    
    | 표기 | 허용 범위 |
    | --- | --- |
    | `~> 7.2` | 7.2 이상, 8.0 미만 |
    | `~> 7.2.4` | 7.2.4 이상, 7.3.0 미만 |
    | `>= 7.2` | 7.2 이상 (상한 없음) |
    | `7.2.4` | 정확히 7.2.4 |

```ruby
source "https://rubygems.org"                       # gem을 어디서 받을지 지정 (공식 저장소: RubyGems.org)

gem "jekyll-theme-chirpy", "~> 7.6"                 # 사용할 gem을 선언

gem "html-proofer", "~> 5.0", group: :test          # 용도별로 묶음

platforms :windows, :jruby do                       # 특정 운영체제에서만 설치할 gem을 지정
  gem "tzinfo", ">= 1", "< 3"
  gem "tzinfo-data"                                 # Windows 계열에서 타임존 데이터
end

gem "wdm", "~> 0.2.0", :platforms => [:windows]     # Windows 파일 변경 감지 (로컬 serve 자동 갱신)
```

#### 4-3. index.html

- `---`로 감싼 부분이 머리말
    - Jekyll은 이 블록이 있는 파일만 처리 대상으로 삼음
    - 내용이 비어 있어도 `---`가 있어야 함
- `layout: home`
    - gem 안의 `_layouts/home.html`을 쓰라는 뜻
    - 홈의 글 목록·페이지네이션은 전부 그 레이아웃이 만들고, 이 파일은 "어떤 레이아웃을 쓸지"만 지정

```html
---
layout: home
# Index page
---
```

<details markdown="1">
<summary>pages-deploy.yml 전체 보기</summary>

```yaml
name: "Build and Deploy"
# 실행 조건
on:
  push:
    branches:
      - main
      - master
    paths-ignore:
      - .gitignore
      - README.md
      - LICENSE

  # Actions 탭에서 수동 실행을 허용
  workflow_dispatch:

# 워크플로에 부여할 권한 - Pages 배포에 필요한 최소 권한만 줍
permissions:
  contents: read
  pages: write
  id-token: write

# 동시 배포를 막음 - 새 실행이 시작되면 진행 중이던 것을 취소
concurrency:
  group: "pages"
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      # 저장소를 받아옴
      # 0: 전체 커밋 이력을 받음 - 수정일 플러그인이 git 이력을 읽어야 해서 필요
      - name: Checkout
        uses: actions/checkout@v7
        with:
          fetch-depth: 0

      # Pages 설정을 읽어 base_path 같은 값을 뒤 단계에 넘김
      - name: Setup Pages
        id: pages
        uses: actions/configure-pages@v6

      # Ruby 설치, bundle install 실행, 설치된 gem을 캐시해 다음 실행을 빠르게 함
      - name: Setup Ruby
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: 3.4
          bundler-cache: true

      # 실제 빌드
      - name: Build site
        run: bundle exec jekyll b -d "_site${{ steps.pages.outputs.base_path }}"
        env:
          JEKYLL_ENV: "production"

      # 빌드 결과의 링크·이미지 경로를 검사
      - name: Test site
        run: |
          bundle exec htmlproofer _site \
            \-\-disable-external \
            \-\-ignore-urls "/^http:\/\/127.0.0.1/,/^http:\/\/0.0.0.0/,/^http:\/\/localhost/"

      # 빌드 결과물을 Pages가 가져갈 수 있는 형태로 업로드
      - name: Upload site artifact
        uses: actions/upload-pages-artifact@v5
        with:
          path: "_site${{ steps.pages.outputs.base_path }}"

  # 빌드 성공 후에만 실행, deploy-pages가 업로드된 산출물을 실제 사이트로 게시
  deploy:
    # GitHub UI에 배포 환경과 주소를 표시
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

#### 4-6. _tabs/*.md

- 선택 사항
- **`_tabs`**: 사이드바 메뉴 항목
- `_config.yml`에 `collections: tabs:` 가 정의돼 있어서, 이 폴더의 파일들은 탭(메뉴) 컬렉션으로 처리됨
- 파일 하나가 메뉴 하나
- `layout`
    - gem이 제공하는 레이아웃 이름
    - `categories`, `tags`는 글 데이터를 모아 목록을 자동 생성
- `icon`
    - 사이드바 아이콘
    - Font Awesome 클래스명
- `order`
    - 메뉴 정렬 순서
    - `_config.yml`의 `sort_by: order`가 이 값을 기준으로 정렬

```markdown
---
layout: categories
icon: fas fa-stream
order: 1
---
```

```ruby
#!/usr/bin/env ruby
#
# Check for changed posts

Jekyll::Hooks.register :posts, :post_init do |post|

  commit_num = `git rev-list --count HEAD "#{ post.path }"`

  if commit_num.to_i > 1
```

### 5. 테마 다운 받기

#### 5-1. bundle install

- `Gemfile` 파일을 만든 후 터미널에서 `bundle install`을 실행하면, Chirpy 테마가 gem으로 다운로드 됨
- `_layouts`, `_sass` 등 테마 내용물
    - 사용자 폴더가 아닌 gem 저장 위치에 설치됨
    - 빌드할 때 Jekyll이 알아서 가져다 씀
- **`bundle install`**: Gemfile을 읽어 gem을 설치하고 Gemfile.lock을 만듦
- **`bundle exec 명령어`:**
    - Gemfile.lock에 기록된 정확한 버전으로 명령을 실행
    - Jekyll을 `jekyll serve`가 아니라 `bundle exec jekyll serve`로 실행
    - 시스템에 깔린 다른 버전이 아니라 이 프로젝트가 지정한 버전을 쓰기 위함
- **`bundle update`:** Gemfile의 범위 안에서 gem을 최신으로 올리고 Gemfile.lock을 갱신

```bash
bundle install
```

#### 5-2. Gemfile.lock

- `bundle install`을 실행하면 `Gemfile.lock`이 자동 생성됨
- 실제로 설치된 정확한 버전(예: 7.2.4)과 그 gem들이 다시 의존하는 하위 gem 목록까지 전부 기록됨
- `.gitignore`에 넣어 커밋 제외
    - Chirpy starter는 `.gitignore`에 포함해 커밋하지 않음
    - 일반적인 Ruby 애플리케이션에서는 커밋하는 것이 관례이나, 이 템플릿은 CI에서 매번 해결하는 방식을 택함

### 6. 실행 및 커밋

#### 6-1. 실행

- 로컬에서 실행
    
    ```bash
    bundle exec jekyll serve
    ```
    
- 종료 단축키: `Ctrl + C`

#### 6-2. 빌드, 배포

- `git push` 시 GitHub Actions가 빌드·배포를 수행하고 사이트에 반영됨
- `_site`
    - 빌드 산출물이므로 커밋하지 않음 (`.gitignore` 에 들어있음)
    - 커밋하면 글 하나 고칠 때마다 수백 개 파일이 변경으로 잡히고, 저장소가 불필요하게 커지며, 로컬 빌드 결과와 CI 빌드 결과가 충돌함
    - 배포되는 것은 GitHub Actions가 서버에서 새로 빌드한 `_site`이고, 저장소가 아니라 아티팩트로 Pages에 전달됨
- gem은 Actions 워크플로가 받음
    - `pages-deploy.yml`의 정의됨
        
        ```yaml
        - name: Setup Ruby
          uses: ruby/setup-ruby@v1
          with:
            ruby-version: 3.4
            bundler-cache: true    # ← 이 옵션이 bundle install 을 실행
        ```
        
    - 러너에서 `bundle install`을 실행하고, 설치된 gem을 캐시해 다음 빌드를 빠르게 함
    - Actions 러너가 `Gemfile`을 읽고 RubyGems에서 Chirpy 테마를 내려받은 뒤 빌드함
    
    | 저장소에 올라가는 것 | 서버가 만드는 것 |
    | --- | --- |
    | `_posts`, `_tabs`, `_config.yml`, `Gemfile` 등 | gem 설치, `_site` 빌드, 배포 |
