## Jekyll/Chirpy 블로그가 만들어지는 흐름(생명주기)

![image.png](image.png)

1. **작성**
    - `_posts/2026-08-09-제목.md` 같은 파일에 마크다운으로 글을 작성
    - 파일 맨 위엔 `---`로 감싼 머리말(front matter)이 들어감
        - 제목, 날짜, 카테고리, 태그 같은 글의 정보를 적는 칸
2. **설정**
    - `_config.yml`에 사이트 전역 설정(제목, 언어, 소셜 링크 등)이 있음
3. **빌드**
    - Jekyll이 글 + 테마의 템플릿(`_layouts`, `_includes`) + 스타일(`_sass`)을 합쳐서 
    완성된 HTML 사이트(`_site/` 폴더)를 만듦
4. **배포**
    - GitHub Actions가 그 빌드를 대신 실행해 GitHub Pages에 올리고, 웹에 공개됨

---

### Jekyll

- 마크다운으로 쓴 글을 웹페이지(HTML)로 구워주는 엔진
- 정적 사이트 생성기(static site generator)
- 글만 쓰면 Jekyll이 디자인 입혀서 완성된 사이트로 만들어 줌

### Ruby

- 프로그래밍 언어
- Jekyll는 Ruby로 만들어짐
    - Jekyll을 돌리려면 컴퓨터에 Ruby 설치 필요
    - 사용자가 Ruby 코드를 작성하는 게 아닌, 엔진이 돌아가기 위해 필요

### gem

- Ruby의 패키지 단위
- gem 방식:
    - 테마를 하나의 부품처럼 **빌려다 쓰는** 것
    - 업데이트는 부품 버전 숫자만 바꾸면 됨
- ex) Jekyll, Chirpy 테마

### **GitHub Pages**

- 완성된 HTML을 무료로 웹에 띄워주는 호스팅

---

### Ruby/Jekyll vs Node/JavaScript

| **역할** | **Ruby / Jekyll** | **Node / JavaScript** |
| --- | --- | --- |
| 언어 | Ruby | JavaScript |
| 실행 런타임 | Ruby 인터프리터 | Node.js |
| 패키지 관리자 | gem + Bundler | npm (yarn·pnpm) |
| 의존성 파일 | Gemfile | package.json |
| 사이트 생성기 | Jekyll | Astro · Eleventy · Next 등 |
| 테마 예시 | Chirpy | 생성기별 테마 |
| GitHub Pages | 네이티브 지원 | Actions로 빌드 필요 |
| 최종 결과물 | 정적 HTML | 정적 HTML (동일) |

## 테마(Chirpy)를 가져오는 방식

Chirpy 공식 문서: "Jekyll에 익숙하고 테마를 직접 수정·기여할 게 아니면 fork 방식은 권장하지 않는다"고 명시 (Starter가 기본 권장안)

|  | 풀 소스 방식 (지금) | Starter 방식 |
| --- | --- | --- |
| 관리 파일 | 테마 소스 전체 | 사용자 글 + `_config.yml` 정도만 |
| 업그레이드 | upstream 태그를 merge → **충돌 잦음** | `Gemfile`의 gem 버전만 올림 |
| 커스터마이징 자유도 | 높음 (내부 다 수정 가능) | 필요한 파일만 같은 경로에 두면 override |
| 공식 권장 대상 | Jekyll에 익숙하고 테마를 수정할 사용자 | 대부분의 사용자 (글쓰기 위주) |

![image.png](image1.png)

### fork 방식

- 테마 소스 전체를 내 저장소에 복사
- 테마 디자인·기능을 코드로 직접 수정할 사람용
- 업데이트 번거로움
    - 최신 테마를 받으려면 어느 방식이든 **직접** 가져와야 함
- fork 배너 있음

### Starter(gem) 방식

- 테마를 부품으로 빌려 씀
    - 테마는 사용자의 저장소 **밖**에 설치되고 Jekyll이 빌드할 때 가져다 씀
- 글쓰기 위주로 쓰고 색·사이드바 정도만 수정할 사람용
    - 사용자의 저장소엔 글·설정만
    - `_posts` 폴더에 글 올리고 push하면 끝
- 업데이트 쉬움
    - `Gemfile`에서 버전 숫자 하나만 올리고 `bundle update` 하면 끝
    - 충돌 없음
- fork 배너 없음

#### gem 방식의 저장소 폴더

- `_layouts`, `_includes`, `_sass` 같은 테마 내부는 gem 안에 들어있어서 사용자 폴더엔 안 보임
- 관리가 단순해짐
- fork 방식은 다 밖에 나와 있어서 복잡함

| 폴더/파일 | 역할 |
| --- | --- |
| `_config.yml` | 사이트 설정 |
| `_posts/` | 내가 쓴 글 (마크다운) |
| `_tabs/` | 상단 메뉴 페이지 (About 등) |
| `assets/img/` | 내가 넣는 이미지 |
| `Gemfile` | 어떤 gem(테마 포함)을 쓸지 |
| `.github/workflows/` | 배포 자동화 |
