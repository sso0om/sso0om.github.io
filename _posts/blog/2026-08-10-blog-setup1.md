## 왜 깃블로그는 대부분 정적인가

- 직접적인 원인: 호스팅 계층의 제약
- 깃블로그: Git 기반 정적 호스팅(GitHub Pages, GitLab Pages 등)에 배포하는 블로그
- 호스팅 계층은 정적 파일만 HTTP로 서빙하고, 서버 측 런타임이나 데이터베이스를 실행하지 않음
    - WordPress(PHP)나 Rails 같은 동적 서버 애플리케이션은 애초에 배포가 불가능하고
    - 배포할 수 있는 것은 정적 사이트로 한정됨
- 정적 방식의 이점
    - 서버·DB를 운영하지 않으므로 호스팅이 무료 또는 저비용
    - 서버 측 공격 표면이 없어 보안상 유리함
    - 사전 렌더링된 파일을 CDN으로 배포해 응답이 빠름
    - 콘텐츠가 텍스트 파일이라 Git 버전관리 워크플로와 잘 맞음
    - 운영 부담도 최소

⇒ 이 특성들이 개인 블로그 요건과 부합해 정적 방식이 사실상 표준 선택지가 됨

### 정적 사이트 VS 동적 사이트

정적(static)과 동적(dynamic)의 차이: HTML을 만드는 시점

![image1.png](/assets/img/posts/blog/2026/blog-setup1/image1.png)

#### **동적 사이트**

- HTTP 요청이 올 때마다 서버 측 애플리케이션(PHP, Node.js, Ruby on Rails 등)이 실행됨
- 서버가 데이터베이스를 조회하고, 그 데이터를 템플릿에 결합해 HTML을 런타임(요청 시점)에 생성한 뒤 응답함
- 요청·사용자·시점에 따라 다른 결과를 반환할 수 있음
- HTML 생성: 요청 시점 렌더링

#### 정적 사이트

- 서버에는 미리 생성된 HTML/CSS/JS 파일이 저장돼 있음
- 요청이 오면 웹 서버는 해당 경로의 파일을 그대로 응답
- 서버 측 연산이나 DB 조회가 없고, 애플리케이션 서버도 실행되지 않음
- HTML 생성: 사전 렌더링

#### 정적 사이트 생성기

- 빌드 시점에 소스(마크다운 콘텐츠 + 템플릿 + 데이터)를 입력받아 완성된 정적 HTML 파일 집합을 산출하는 도구
- 렌더링 작업을 요청 시점에서 빌드 시점으로 이동시키는 것이 SSG의 본질
- Jekyll: Ruby로 구현된 SSG

## GitHub Pages의 구조

빌드(Actions)와 서빙(Pages)을 **모두** 수행하되, 
서빙 계층이 정적 파일만 다루기 때문에 배포 가능한 것은 정적 사이트로 한정된다

### 1. 빌드 계층

- GitHub Actions 워크플로가 러너에서 `jekyll build`를 실행해 산출물(`_site`)을 생성

### 2. 서빙 계층

- 빌드 산출물을 GitHub Pages의 정적 파일 서버(CDN 포함)가 HTTP로 서빙
- 애플리케이션 서버나 데이터베이스를 실행하지 않음
- 정적 자산만 응답할 수 있음

## 동적 처리

동적 부분을 정적 호스트가 아니라 외부로 옮겨서 처리함

### **JAMstack**

- 정적 마크업 + 외부 API + 클라이언트 JavaScript로 동적 기능을 구성하는 아키텍처
- **정적 사이트:** 정적 파일만 서빙
- **외부 서비스:** 동적인 부분(집계·저장·조회)은 전부 담당
- **브라우저의 JavaScript:** 정적 사이트와 외부 서비스를 연결

#### **예시 - 방문자 수**

클라이언트 측 JavaScript + 외부 서비스 방식으로 구현

1. **수집**
    - 각 페이지에 분석용 JavaScript 스니펫이 들어감
    - 방문자의 브라우저가 페이지를 로드할 때 이 스크립트가 실행되어, 외부 분석 서비스의 엔드포인트로 HTTP 요청(방문 이벤트, 이른바 "hit")을 보냄
    - 이 요청을 받아 **집계하고 데이터베이스에 저장하는 것은 그 외부 서비스의 서버**
    - 사용자의 정적 호스트(GitHub Pages)가 아닌, 제3자 인프라에서 동적 연산 발생
    - 브라우저 JavaScript 실행에 의존하므로, 방문자가 JavaScript를 차단하거나 광고·추적 차단기를 쓰면 그 방문은 집계에서 누락됨
        - 서버 로그 기반 집계와 달리 완전하지 않음
2. **표시**
    - 집계된 방문자 수를 페이지에 보여줌
    - 브라우저의 JavaScript가 그 외부 서비스의 API를 호출해 현재 수치를 받아온 뒤 DOM에 렌더링함
